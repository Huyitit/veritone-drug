initiateMultipartUpload(input: InitiateMultipartUploadInput!): MultipartUploadSessionInfo

This mutation creates the multipart upload session to an S3 bucket. If provided, it will create the session for a
specified bucket. Otherwise, it will create a session for the API bucket that is configured for aiware by default.
What this mutation does is establish a connection to the bucket, initiate the multipart upload session,
and generate pre-signed URLs for each part that needs to be uploaded. The number of generated pre-signed URLs is
determined by the numberOfParts input field.
Example:
Request:
mutation {
initiateMultipartUpload(input: {
fileName: "exampleImage.jpg",
contentType: "image/jpeg",
fileSize: 22594,
}) {
preSignedUrls {
partNumber
signedUrl
}
chunkSize
key
uploadId
}
}

This mutation is called after all parts have been uploaded. This will finalize and close out the
multipart upload session and return the final URL where the file was uploaded to.
Example:
Request:
mutation {
completeMultipartUpload(input: {
key: "exampleImage.jpg",
uploadId: "exampleUploadId",
parts: [
{
partNumber: "1",
etag: "exampleEtag"
}
]
}) {
url
}
}

cancelMultipartUpload(input: CancelMultipartUploadInput!): DeletePayload

This mutation can be called at any point during an open multipart upload session.
This will cancel the session and free up any space taken up by any parts already uploaded.
However, it is possible for there to be dangling parts that may have still been in-progress and
uploaded after the cancel request was made. This mutation will make the cancel request up to 3 times
to ensure that everything has been cleaned up properly. If it’s not fully clean after 3 calls,
an error will be returned, directing to run this mutation again.
Example:
Request:
mutation {
cancelMultipartUpload(input: {
key: "exampleImage.jpg",
uploadId: "exampleUploadId"
}) {
id
message
}
}

ingestSlugsCreate(input: IngestSlugsCreateInput!): IngestSlugsCreateResult

Create one or more ingest slugs in bulk.

This mutation creates ingest slug records for files, enabling tracking through
the ingestion pipeline. It supports batch processing (up to 1000 files per batch),
returns both successful creations and failures, and validates sourceId and optional
engineId and appId parameters. The organizationId is retrieved from the user's
authorization context.

Requires scope: superadmin OR aiware.slug.create

Example: Create multiple ingest slugs for a video source:
mutation {
ingestSlugsCreate(
input: {
sourceId: "100"
files: [
{
fileUri: "s3://bucket/videos/file1.mp4"
bundleKey: "bundle-001"
mimeType: "video/mp4"
fileSizeBytes: 2147483648
fileCreatedAt: "2024-01-15T10:00:00Z"
fileModifiedAt: "2024-01-15T10:30:00Z"
status: "pending"
},
{
fileUri: "s3://bucket/videos/file2.mov"
bundleKey: "bundle-001"
mimeType: "video/quicktime"
fileSizeBytes: 1073741824
fileCreatedAt: "2024-01-15T11:00:00Z"
fileModifiedAt: "2024-01-15T11:30:00Z"
status: "pending"
}
]
engineId: "c0e55cde-340b-44d7-bb42-2e0d65e98255"
appId: "47bd3e25-f4ea-435f-b69b-13cb4f9dd60a"
}
) {
sourceId
created {
sourceId
fileUri
status
bundleKey
createdAt
}
failed {
fileUri
errorCode
errorMessage
}
}
}

Response:
{
"data": {
"ingestSlugsCreate": {
"sourceId": "100",
"created": [
{
"sourceId": "100",
"fileUri": "s3://bucket/videos/file1.mp4",
"status": "pending",
"bundleKey": "bundle-001",
"createdAt": "2024-01-15T09:00:00Z"
},
{
"sourceId": "100",
"fileUri": "s3://bucket/videos/file2.mov",
"status": "pending",
"bundleKey": "bundle-001",
"createdAt": "2024-01-15T09:05:00Z"

  • Duplicate file URIs for the same source are ignored and returned as failures

  • If tdoId is provided, the slug will be associated with that temporal data object
  • organizationId is automatically determined from the user's authorization context
ingestSlugUpdate(
sourceId: ID!
fileUri: String!
input: IngestSlugUpdateInput!
): IngestSlug

Update an individual ingest slug's metadata with optional conditional filtering.

Allows updating file metadata, processing status, and TDO/asset associations
for a specific ingest slug identified by sourceId and fileUri. Only provided fields
are updated (partial updates are supported). The updatedAt timestamp is automatically
updated. The sourceId is scoped to the user's organization from their authorization context.

Optional filtering can be applied to restrict updates to slugs in a specific status,
useful for preventing concurrent updates or ensuring updates only occur on files
in a particular state.

Requires scope: superadmin OR aiware.slug.update

Example 1: Update slug status and associate with a TDO:
mutation {
ingestSlugUpdate(
sourceId: "100"
fileUri: "s3://bucket/videos/sample.mp4"
input: {
status: "ingested"
statusMessage: "Successfully ingested and transcoded"
tdoId: "1570654874"
assetId: "1570654874_4hJtNKSUXD"
mimeType: "video/mp4"
fileSizeBytes: 2147483648
}
) {
sourceId
fileUri
status
statusMessage
tdoId
assetId
mimeType
fileSizeBytes
updatedAt
}
}

Example 2: Update file metadata timestamps:
mutation {
ingestSlugUpdate(
sourceId: "100"
fileUri: "s3://bucket/videos/sample.mp4"
input: {
fileModifiedAt: "2024-01-15T14:00:00Z"
bundleKey: "bundle-updated"
}
) {
fileModifiedAt
bundleKey
updatedAt
}
}

Example 3: Conditional update - only update if status is currently 'pending':
mutation {
ingestSlugUpdate(
sourceId: "100"
fileUri: "s3://bucket/videos/sample.mp4"
input: {
status: "ingested"
filter: {
status: "pending"
}
}
) {
sourceId
fileUri
status
updatedAt
}
}

Response:
{
"data": {
"ingestSlugUpdate": {
"sourceId": "100",
"fileUri": "s3://bucket/videos/sample.mp4",
"status": "ingested",
"statusMessage": "Successfully ingested and transcoded",
"tdoId": "1570654874",
"assetId": "1570654874_4hJtNKSUXD",
"mimeType": "video/mp4",
"fileSizeBytes": 2147483648,
"updatedAt": "2024-01-15T14:00:00Z"
}
}
}

Notes:

  • Both sourceId and fileUri are required and used as composite key
  • Any combination of updatable fields can be provided
  • TDO/asset associations are upserted
  • The returned object contains all current slug fields after the update
  • sourceId is validated to belong to the user's organization from authorization context
  • filter.status can be used to make updates conditional on current status
  • If filter.status is provided and current status doesn't match, returns null (not found)
